# CSMPR Player Performance Prediction

Reproducible analysis repository for an MSc dissertation investigating **next-season relative performance prediction for elite football players** across Europe's five major leagues.

The analysis is deliberately chronological. A player-season at season `t` contains only information available by the end of that season and is used to predict the player's role-specific performance percentile in season `t+1`.

## Data source

The source dataset is **Top 5 League Football Player Stats (2017–2025)** by Emre Yılmaz, obtained from Kaggle:

https://www.kaggle.com/datasets/emrey3lmaz/top-5-league-football-player-stats-2017-2025

The source data are not committed to this repository. This keeps third-party data separate from the analysis code and avoids redistributing the dataset independently of the conditions stated on its Kaggle data card. To reproduce the analysis, download the dataset and place the semicolon-delimited source CSV at:

`data/raw/Dataset_Original.csv`

## Analysis sequence

Run the notebooks in numeric order:

1. `01_data_audit_and_player_season_panel.ipynb` — source import, duplicate/identity audit and one-row-per-player-season aggregation.
2. `02_role_specific_performance_target.ipynb` — role-aware performance-index construction, validation and 900-minute target-level sensitivity.
3. `03_longitudinal_feature_engineering.ipynb` — leakage-safe current-performance, trajectory, age/exposure, context and role-conditional predictors.
4. `04_chronological_model_evaluation.ipynb` — four expanding-window outer tests, inner chronological tuning and regression/mixed-effects comparison.
5. `05_feature_group_ablation.ipynb` — nested and leave-one-group-out feature analysis with independent retuning for every fold × specification.
6. `06_error_direction_practical_uncertainty.ipynb` — selection coverage, subgroup/error analysis, directional classification, shortlist retrieval, prediction intervals and player-cluster bootstrap comparisons.

## Chronological evaluation

Eight source seasons create seven possible season-to-season transitions. The earliest transitions initialise the training history; four expanding-window outer folds are used for genuine future evaluation:

- forecast origin 2020/21 → target 2021/22
- forecast origin 2021/22 → target 2022/23
- forecast origin 2022/23 → target 2023/24
- forecast origin 2023/24 → target 2024/25

The final evaluation contains 4,742 held-out player-season transitions. Headline pooled metrics are calculated from the concatenated out-of-fold predictions, so every evaluated transition contributes once.

## Leakage controls

- Player histories use exact season offsets; gaps remain missing.
- The primary supervised sample requires an eligible role-specific target at `t` and `t+1` and the same broad role in both seasons.
- No random train/test split is used for the primary forecasting analysis.
- Imputation, missingness indicators, constant-column removal and scaling are fitted from training data only.
- Tunable models use a chronological validation period inside each outer-training window.
- Feature ablations are independently retuned for every feature specification.
- The mixed-effects model applies player-specific BLUP adjustments only when the test player has previously appeared in the training history; unseen players remain in the sample through the fixed-effects prediction.

## Reproducing the analysis

Install the pinned Python dependencies:

```bash
pip install -r requirements.txt
```

Place `Dataset_Original.csv` in `data/raw/`, then run:

```bash
python run_all.py
```

The script executes the six notebooks in order, runs reproducibility/integrity checks, and rebuilds the analysis manifest.

## Repository contents

- `notebooks/` — executed analysis notebooks in research order.
- `src/` — shared chronological preprocessing and evaluation utilities.
- `config/` — model grids and fixed analysis settings.
- `results/tables/` — aggregate/report-ready numerical outputs.
- `results/figures/` — figures generated by the analysis.
- `data/README.md` — source-data acquisition and expected local paths.
- `analysis_manifest.json` and `MANIFEST_SHA256.csv` — version/environment metadata and hashes for repository-tracked analytical files.

Local raw/processed datasets and row-level predictions are intentionally excluded from Git through `.gitignore`. They are regenerated locally when the analysis is executed.
